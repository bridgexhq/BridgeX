Security & privacy

FileBird holds the keys to your servers, so it is built to deserve that.

Passwords and passphrases live only in your system keychain

They never reach a settings file, a log, or the part of the app that draws the screen.

Private keys are read only at the moment you connect

Reading happens in the background part of the app. The interface only ever sees a summary: type, fingerprint, and whether a passphrase is needed.

Every server's identity is verified on every connection

A changed key stops the connection rather than warning you after the fact.

Terminal output is never logged, at any level

A terminal routinely shows passwords, keys and whole environments.

The window that draws the interface has no access to your files, network, or system

It asks the background part of the app for everything, one named request at a time, and every request is checked again on arrival.

Nothing is sent anywhere

No accounts, no telemetry, no update pings. The app only ever talks to the servers you tell it to.

Worth knowing

What FileBird doesn't do yet

  • No SSH agent, ProxyJump or hardware keys yet.
  • ~/.ssh/known_hosts is not read — FileBird keeps its own list of trusted servers, built up as you connect.
  • Builds are ad-hoc signed, not notarised or certificate-signed, so macOS and Windows each warn once on first open. See Download for what that looks like and why.
